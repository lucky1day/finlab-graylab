# 逐 Request 重算与 walk-forward 类算法的成本观察（2026-08-06）

**文档状态**：`HISTORICAL`

**适用运行时**：`blackbox_v2`

**目标读者**：平台入库、上游契约维护和 Harness 维护人员

**最后核验日期**：2026-08-06

本记录是一次入库过程中的时点观察与证据。第 1~3 节为观察与证据；第 4 节记录
据此在同日采纳的合同改动；第 5 节记录仍然未解决的部分。本记录本身不定义规则，
规则以[上游交付 SOP](../../sop/BLACKBOX_V2_UPSTREAM_DELIVERY_V1.md) §6.3 为准。

## 1. 现象

Contract 1.0 要求批量回测对每条 Request 按自己的截止键独立截断，并明确禁止按
批次最大截止键一次截断后复用（[上游交付 SOP](../../sop/BLACKBOX_V2_UPSTREAM_DELIVERY_V1.md) §6.3）。

对于**自身就是 walk-forward 结构、一次运行即产出整条逐周预测序列**的算法，这条
要求会把 O(1) 的计算放大成 O(N)：平台把 N 条 Request 交给 `backtest`，算法必须
把同一条 walk-forward 序列从头重算 N 遍，每遍只取最后一行作为该 Request 的结果。

在 `cgb_causal_wk_1y_v128` 的入库中观测到：

| 项目 | 观测值 |
|---|---|
| 单次全历史 walk-forward | 约 75 秒 |
| 一次运行产出的逐周预测 | 381 行 |
| Backtest Gate 固定 no-persist 条数 | 100 条 |
| 该 Gate 因此耗时 | 约 125 分钟 |
| 周度方案完整持久化回测（`2025-01-01` 起）条数 | 约 70~75 条 |

即：一次运行就能得到的 381 个周点结果，被拆成 100 次（Gate）与约 74 次（持久化
回测）完整重算。

## 2. 证据：该算法在抽样周点上表现为严格因果

用同一份输入做了两种跑法的对照——一次跑完整历史取逐周结果，与按各自截止键
逐条截断后取末行结果：

| week_id | 一次全历史 | 逐条截断 | 是否一致 |
|---|---|---|---|
| 202627 | `pred_label=-1`, `prob_up=0.389970` | `pred_label=-1`, `prob_up=0.389970` | 是 |
| 202628 | `pred_label=1`, `prob_up=0.563308` | `pred_label=1`, `prob_up=0.563308` | 是 |
| 202629 | `pred_label=-1`, `prob_up=0.460704` | `pred_label=-1`, `prob_up=0.460704` | 是 |

`202627` 的截断输入比全历史少三个周点，结果仍逐位相同，说明在该区间内后续周的
数据没有回流到更早周点的预测中。

**这三条只是抽样证据，不是因果性证明。** 三个样本都位于序列末端，训练窗口形态
接近；更早周点（尤其是 warmup 边界、模型选择窗口切换处）未做对照。任何据此放宽
截断要求的做法都缺乏依据。

## 3. 为什么现行规则仍然必须遵守

逐条截断的价值不在于它比一次 pass 算得更准，而在于**它把「算法内部是否存在前视」
这件事从信任问题变成结构问题**。平台不反编译、不审计算法内部逻辑，因此无法验证
全样本 fit、未来窗口调参、中心化滚动统计这类泄漏。逐条截断在输入边界上物理排除
了这类泄漏，使结论不依赖对上游的信任。

如果交付件内部改成按批次最大截止键一次截断再切片：

- 七个自动 Gate 全部不会报错，因为它们检测不到这种内部行为；
- 回测结果会因潜在泄漏而偏乐观，且无法从证据链上发现。

正因为**检测不到**，这条规则必须靠流程纪律守住，而不是靠 Gate 兜底。

## 4. 同日采纳的合同改动

[上游交付 SOP](../../sop/BLACKBOX_V2_UPSTREAM_DELIVERY_V1.md) §6.3 已放开为：批量
回测的默认语义仍是逐行独立截断，但 walk-forward 类算法可以在内部使用**等价的
一次性计算**，前提是同时满足三条：

1. **结果等价**：每条 Request 的五个业务字段必须与独立截断结果完全一致；
2. **批内自证**：算法在每个批次内实际抽样复算并逐字段比对，样本至少覆盖批内
   首条、中间一条和末条，比对必须走独立截断路径，且包含算法内部方向与概率字段；
3. **失败回退**：任一抽样不一致即整批回退到逐条独立截断，并写入 `stderr`。

抽样必须确定性选取，不得使用随机数。§5 的「结果不得因批次大小、批次切分或输入
顺序改变」保持为不变量；§9 自验表新增一行专门核对该模式；§10 检查清单同步。

成本从「N 次完整重算」降为「1 次完整重算 + 3 次抽样复算」。对本记录观测的算法，
Backtest Gate 的 100 条与周度完整持久化回测的约 74 条，都降为各 4 次完整计算。

`cgb_causal_wk_1y_v128` 是第一个按该模式实现的交付件。

## 5. 仍然未解决的部分

- **自证在交付件内，不在 Gate 内。** 平台仍然无法独立检测算法是否诚实执行了
  批内自证；Backtest Gate 的证据边界已在[平台入库 SOP](../../sop/BLACKBOX_V2_PLATFORM_ONBOARDING_V1.md) §4.2
  明确标注为「不证明」。把抽样对照上提到 Gate 侧会更强，但需要 Harness 改动，
  尚未实施。
- **抽样覆盖面有限。** 首/中/末三点无法覆盖 warmup 边界、模型选择窗口切换等
  形态突变处。若某算法只在这些位置存在前视，当前抽样可能漏检。
- **第 2 节仍只是三点抽样观察**，不构成对该算法因果性的证明。

## 6. 本记录不主张什么

- 不主张任何已入库方案的回测结果存在问题；
- 不为**没有实现批内自证**的交付件走一次性计算提供任何依据；
- 不放宽截止键定位规则、批次不变量或任何其它现行约束。
