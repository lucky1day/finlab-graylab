# 特征基准日统一展示：需求与本地验收方案

**状态：需求已确认，本地候选待用户验收，尚未发布。**

本文记录本次展示调整的业务目标、范围和验收条件。运行日期与统计定义由
[预测语义](../architecture/PREDICTION_SEMANTICS.md)维护，接口实现见
[Dashboard 合同](../operations/PUBLIC_FACTOR_LAB_PERFORMANCE.md)。本文件不代表线上版本已更新。

本次本地验收入口：[http://localhost:18120/](http://localhost:18120/)，仅限本机访问，
无需线上账号登录。页面底部注明离线快照时间；点击“应用区间”后更新顶部日级统计。

## 1. 核心目标

灰度实验室以**特征基准日**统一确定时间筛选、回测/实盘展示分类、月份归属及统计范围。
预测日解释信号发出时间；目标日或目标周期解释预测对象及验证结果；原始执行来源保留用于审计。

页面明确提供两种查看范围：

- **区间统计**：顶部矩阵、方案排行及相应指标，严格使用所选起止日之间的预测记录。
- **整月详情**：选中方案的月度统计、趋势和每日验证明细，展示所选区间涉及月份的完整记录。

两者都按特征基准日选取记录，并遵循同一个回测/实盘筛选。整月详情是用户明确要求的范围扩展，
因此不能再笼统描述为“所有位置始终使用同一批记录”。同一范围内的指标、趋势和明细必须可核对。

## 2. 日期字段的职责

| 字段 | 页面含义 | 用途 |
|---|---|---|
| 特征基准日 `feature_date` | 模型使用数据的截止日、预测站位日 | 筛选、展示分类、统计范围、自然月份归属 |
| 预测日 `predict_date` | 信号发出日 | 解释信号何时发出，保留既有可见性检查 |
| 目标日 `target_date` / 目标周期 | 预测需要验证的日期或业务周期 | 展示预测对象，并与对应实际结果关联 |

以上职责适用于日频、周频、月频、周均、月均、季均、年均等全部现有任务。
跨月、跨季或跨年的目标不会把预测记录移动到目标所属月份。

例如，某条记录特征基准日为 2026-05-29、预测日为 2026-06-01、目标日为 2026-06-05：
它归属 2026 年 5 月，展示分类为回测；表中仍显示原预测日、目标日及其验证结果。
这项展示分类不改变该条记录原来的执行来源。

## 3. 顶部筛选与区间统计

1. 起止日期精确到日，显示完整年月日，不再只提供年月选择。
2. 起止日期均包含在筛选范围内：`开始日 ≤ 特征基准日 ≤ 结束日`。
3. 初次打开及切换展示口径时，默认覆盖当前口径下全部可展示历史，使用实际可见记录的最早、最晚特征基准日。
   “全部历史”仍遵守平台既有可见性边界，不扩大到未展示的历史事实。
4. 顶部矩阵、方案排行及区间指标使用同一日期范围和展示口径。调整日期后重新计算排行。
5. 日历日期不自动挪到交易日；选中的非交易日可以没有记录。开始日晚于结束日时给出明确提示，不展示错误范围的指标。
6. active 方案的可见性、数量及生产标记规则保持原有语义；某个范围没有记录不等于方案被移除。
7. 请求加载或失败时，不把旧范围的统计显示成新范围的结果；快速切换后只接受最新有效请求。

## 4. 回测/实盘展示分类

保留 2026-06-01 这个展示分界日期，将判断字段统一为特征基准日：

| 展示选项 | 记录范围 |
|---|---|
| 回测 | 特征基准日早于 2026-06-01 |
| 实盘 | 特征基准日为 2026-06-01 或之后 |
| 全部 | 两者合并 |

跨分界记录的分类、数量、命中率及排序可能变化，这是口径调整的预期影响。
不改写 run phase、backtest 引用、预测业务键或原始执行证据，也不据展示标签判断是否真实自然运行。

删除每个方案详情中“▼ 实盘口径：target_date ≥ 2026-06-01”一类分界提示，
也不替换成重复的特征基准日公式提示。

## 5. 选中方案的整月详情

1. 月份始终是特征基准日的自然月份，不按目标日或目标周期进行偏移。
2. 详情展示顶部日期区间涉及的完整月份，只扩展这几个自然月，不额外展示其他月份。
3. 月度表、月度趋势、点击月份打开的每日验证表使用相同的整月范围和展示口径。
4. “整月”指当前已有且满足可见性规则的记录；当月尚未发生的日期不会补造记录。
5. 页面清晰区分“区间统计”和“整月详情”，展示适用范围，避免把整月指标理解成局部日期区间指标。

**示例：选择 2026-05-20 至 2026-06-10。**

| 位置 | 特征基准日范围 |
|---|---|
| 顶部矩阵、方案排行、区间指标 | 2026-05-20 至 2026-06-10 |
| 选中方案 5 月详情及明细 | 2026-05-01 至 2026-05-31 |
| 选中方案 6 月详情及明细 | 2026-06-01 至 2026-06-30 |

上表仍叠加“全部/回测/实盘”筛选。例如选择“实盘”，5 月记录不会因整月展示而重新出现。

## 6. 每日验证表和指标

- 第一列新增“特征基准日”；保留“预测日”“目标日/目标周期”“预测方向”“实际方向”“验证结果”。
- 日期展示完整年月日；长周期按业务语义解释目标周期。
- 验证结果仍关联这条预测原本的目标，不能用特征基准日查找 Actual 替代目标日。
- 待验证记录保留在所属月份和明细中，明确显示待验证；不计入已验证样本数、命中率等绩效指标。
- 不改变现有方向、命中、精确率等公式，只改变按哪些特征基准日选入统计。

## 7. 实现与隔离方案

业务调整集中在展示层，精确到日的统计同时需要 Dashboard 只读接口支持。页面继续只使用
`/api/factor-lab/dashboard`，由服务端统一汇总，避免浏览器下载全部明细后维护另一套统计逻辑。

- 在独立 worktree 和临时功能分支中修改，验收前不合并当前集成分支。
- 本地独立端口提供验收页面，使用本地离线展示数据快照；页面注明本地验收及快照时间。
- 本地验收服务不连接生产数据库，不代理线上业务写入，也不启动算法、调度或 Actual 更新。
- 真实展示数据如用于快照，只通过一次性只读查询取得；本地数据与凭据不进入 Git。
- Summary 同时提供日级区间汇总和完整月份汇总；月明细继续按方案、特征月份、展示口径读取。
- 目标关联、预测数据及审计来源保持原有合同，无须重跑算法、重算或覆盖历史预测。

## 8. 用户验收清单

| 场景 | 通过条件 |
|---|---|
| 首次打开、切换全部/回测/实盘 | 默认日期覆盖该口径全部可展示历史，精确到日 |
| 只选择一天 | 区间排行只统计该特征基准日；方案详情仍展示该月完整记录 |
| 选择月中至次月月中 | 区间排行严格按日；详情只展示所涉及的两个完整月份 |
| 特征日在 5 月、目标日在 6 月 | 归属 5 月、回测展示；目标日及验证结果保持对应 |
| 周、月及周期均值方案 | 均按特征自然月展示，目标周期解释正确 |
| 每日验证表 | 可同时理解特征基准日、预测日、目标日/周期；日期完整可读 |
| 待验证及无记录范围 | 待验证不计绩效；无数据不伪造为 0% 命中率，不隐藏 active 方案 |
| 日期快速切换、刷新失败 | 不发生新筛选配旧指标或旧请求覆盖新结果 |
| 方案详情提示 | 不再出现“▼ 实盘口径…”分界横幅 |

本地技术检查包括公共接口合同、边界日期、Actual 关联、日区间和整月范围差异、前端交互及实际浏览器核验。
自动检查通过不代替用户页面验收。
