# 前端实盘预测目标区间文案设计

**日期**：2026-07-21

**状态**：已实施

**范围**：因子实验室“选中方案详情”中的实盘分隔文案

## 目标

所有方案统一只显示正式实盘预测的目标日期起点：

```text
▼ 实盘预测目标区间：YYYY-MM-DD开始
```

日期只使用 `scheduled_live` 阶段的首个 `target_date`，即
`phase_ranges[prediction_phase="scheduled_live"].start_target_date`。不得使用
`predict_date`、`feature_date`、部署日期或最后一条灰度预测的离散目标点替代。

例如正式实盘首个目标日为 `2026-06-18` 时，统一显示：

```text
▼ 实盘预测目标区间：2026-06-18开始
```

## 前端行为

- 删除详情文案中的“实盘发出起点”“灰度实盘（目标期）”“信号发出”和
  “正式调度发出起点”等组合说明。
- 日频、周频、月频及 Blackbox V2/Native V1 共用同一生成逻辑。
- 已存在 `scheduled_live` 时，显示其 `start_target_date` 加“开始”。
- 尚不存在 `scheduled_live` 时，显示 `▼ 实盘预测目标区间：待产生`，不从
  `gray_live` 推导正式实盘起点。
- 后端 `phase_ranges` 保持原始审计语义，不改数据库、不改 API 契约；只修改前端展示。

## 测试与文档

- 前端回归测试覆盖存在和不存在 `scheduled_live` 的两种状态。
- 断言旧文案不再出现，并覆盖日频与周频共用行为。
- 同步更新 Blackbox V2 平台入库 SOP 和当前状态文档；不修改上游算法交付 SOP。

## 非目标

- 不改变 `gray_live` / `scheduled_live` 数据分类。
- 不改变三日期、回测/实盘分界、任务格子或前端月度数据。
- 不补写或重标记任何数据库记录。
