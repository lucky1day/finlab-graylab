# 前端隐藏方案版本指纹设计

**日期**：2026-07-20

**状态**：已确认，待实施

## 目标

前端任何可见区域都不再展示类似 `35e461e60705` 的 `scheme_version` 指纹。后端 API、数据库记录及前端接收的数据继续保留该字段，以维持审计、复现和故障定位能力。

## 当前行为

因子实验室的方案排名行会从方案明细中提取最新 `schemeVersion`，并在方案名称后渲染 `.factor-scheme-version` 徽标。复制为纯文本时，徽标内容会与方案名称连接，看起来像名称末尾附加了一串无解释字符。

当前前端没有其他可见的版本指纹渲染入口。

## 设计

采用“移除渲染、保留数据”的最小方案：

1. 从方案排名行删除版本徽标的生成与拼接。
2. 删除只服务于该徽标的 `latestSchemeVersion` 辅助函数。
3. 删除不再使用的 `.factor-scheme-version` CSS 选择器，同时保留样本不足徽标样式。
4. 保留前端数据规范化中的 `schemeVersion` 字段，不修改 API 合同、数据库字段、运行记录或版本生命周期逻辑。

不采用仅用 CSS 隐藏的方案，因为哈希仍会留在 DOM 中；也不在数据映射阶段删除版本字段，因为这会无必要地削弱客户端诊断信息。

## 测试

在现有 Node VM 前端渲染测试中构造一个包含 `schemeVersion: "35e461e60705"` 的方案：

- 渲染后的排名行必须保留完整方案名称。
- 渲染后的 HTML 不得包含 `35e461e60705`。
- 渲染后的 HTML 不得包含 `factor-scheme-version`。

先添加测试并确认它因当前版本徽标而失败，再实施最小代码修改使其通过，最后运行完整的前端因子实验室测试。

## 非目标

- 不修改后端 `/api/schemes`、`/api/metrics/*` 或回测 API。
- 不修改 `t_scheme_versions`、预测明细中的 `scheme_version` 或版本哈希算法。
- 不改变方案名称、排序、指标、详情、任务格子和灰度标记。

## 验收标准

1. 整个前端不再显示方案版本哈希。
2. 后端和数据库仍能返回并审计 `scheme_version`。
3. 方案排名的其他内容和交互保持不变。
4. 相关前端测试全部通过。
